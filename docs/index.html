A whole robotics stack, small enough to read.

keel is robotics middleware in about 9,000 lines of Rust: fast messaging, real-time control, deployment and tracing, built on what Linux already ships.

What's inside

Every layer, as small as it can be.

keel is a learning project. It asks how a whole robotics stack fits together when each layer is the smallest thing that works, and writes every decision down.

RuntimePrograms exchange messages through shared memory without copying them. Restart policies, a watchdog, and real-time scheduling come from the dataflow file.keel run · keel stop · keel update
ControlJoints, controllers and a simulator, with a loop closed inside its own 1 ms cycle. Talks to motors over CAN, and to microcontrollers.keel-pid · keel-sim · keel-can
ObservabilityEvery message is stamped and traced across machines. Record it, replay it, or keep a flight recorder that saves when something fails.keel top · keel trace · keel replay
DeploymentBuilds named by their hash, with history, rollback, branches and fleets.keel deploy · keel rollback · keel fleet
ProvisioningSet up a machine over SSH, or boot one whose only program is keel. Check that it is fit for a robot.keel provision · keel image · keel doctor

Speed

Message size stops mattering.

At first, every message was copied through the daemon. Now only a small note moves, so an 8 MiB camera frame costs the same to send as a few bytes.

Median round trip for an 8 MiB message, on a log scale, across three versions of the transport.

Down to nanoseconds

Median one-way hop with the receiver spinning, log scale. Only a descriptor moves, so the size of the message doesn't matter.

Between two hyperthreads of one core keel hops in 349 ns against 79 ns for the floor. The few hundred nanoseconds keel adds is the hop touching four cache lines in turn (bell, ring, entry, region header) where the floor touches one. On a laptop a 6.2 MB frame hopped like 64 bytes (574 ns), and reading it then took 79 µs.

Try it

Two commands.

cargo build
./target/debug/keel run examples/pipeline.yml

Then, in another terminal, keel top shows the graph live, keel trace shows where the time goes, and keel stop ends it.
